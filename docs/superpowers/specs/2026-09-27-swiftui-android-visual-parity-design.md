# SwiftUI 네이티브 앱의 Android 화면 비율·스타일 통일

## 목적과 범위

사용자는 여행을 선택하는 첫 화면을 포함해 iPhone과 Android 네이티브 앱이 같은 서비스처럼 보이기를 원한다. `TripPlotNativePreview`의 SwiftUI 화면 전체를 Android `nativepreview`의 현재 화면 구조와 시각적 비율에 맞춘다. 여행·지도·저장·지출·더보기의 다섯 탭과 각 탭에서 여는 상세·편집·일정·정산·백업 화면이 대상이다. 기존 기능, 데이터 형식, 저장소, 여행 선택 상태와 접근성 식별자는 유지한다.

WebView 기반 `TravelPlaner` 출시용 타깃과 Android 앱 자체, 서버·웹 화면은 이 작업의 수정 대상이 아니다. 앱 아이콘, 새 기능, 지도 키 입력 및 실제 Google 지도의 렌더링 검증도 포함하지 않는다.

## 현재 차이와 선택한 접근

Android 앱은 Compose `MaterialTheme`의 녹색·중립색 체계, 약 20~24dp 화면 여백, 곡선 카드와 54dp 이상 주요 버튼, 아이콘·라벨이 있는 하단 메뉴를 사용한다. SwiftUI 앱은 탭과 목록에 iOS 기본 스타일이 남아 있고, 여행 목록은 보라색 강조 카드여서 색상과 크기 계층이 다르다. 특히 `NativeRootView.swift`의 기본 `TabView`와 여러 `List`/`Form` 화면이 Android의 화면 밀도와 다르게 보인다.

다음 중 **공통 시각 규칙을 SwiftUI 컴포넌트로 구현하는 방식**을 선택한다.

1. 선택: Android의 색상·여백·서체 계층·카드·탭바 비율을 SwiftUI에 반영한다. 여행 선택, 뒤로 가기, 입력, 화면 읽기 등 iOS의 동작 특성은 유지한다.
2. 비선택: Android 픽셀을 iPhone에 그대로 복제한다. 기기 안전 영역, 시스템 글꼴, Dynamic Type 차이로 잘림과 조작 문제를 낳고 유지비가 높다.
3. 비선택: 여행 목록만 다시 손본다. 나머지 탭과 상세 화면의 시각적 차이가 남아 “앱 전체가 같아 보인다”는 목적을 충족하지 못한다.

따라서 동일한 논리적 화면 너비에서 콘텐츠 시작선·위계·요소 비율을 맞추되, 상태 표시줄/홈 인디케이터·화면 종횡비·시스템 글꼴의 차이는 허용한다. 색상과 구도는 Android가 기준이며 iOS 기존 보라색은 녹색 계열로 변경한다.

## 시각 규칙

SwiftUI에 `NativePreviewTheme` 역할의 공유 스타일을 둔다. Android `TripPlotApp.kt`의 `lightColors`/`darkColors`를 기준으로 대응 값을 iOS에 정의한다. 라이트 모드의 핵심 값은 primary `#416C62`, primary container `#DDECE3`, background `#F8FAF7`, white card `#FFFFFF`, main text `#25372F`, muted text `#637269`이다. 다크 모드도 Android의 대응 색상 역할을 사용한다. 대비가 필요한 오류·삭제 표시는 플랫폼의 의미색을 유지한다.

| 요소 | 목표 비율 |
| --- | --- |
| 일반 화면 좌우 여백 | 20pt, 상세/편집 화면은 Android 대응 화면의 20~24dp 범위와 일치 |
| 화면 상단·세로 섹션 간격 | 24pt 시작 여백, 16~24pt 주요 섹션 간격 |
| 주요 버튼 | 최소 높이 54pt, 모서리 18pt, Android primary 색상 |
| 대표 여행 카드 | 모서리 26pt, 내부 여백 22pt, 녹색→청색 그라데이션, Android와 같은 정보 순서 |
| 일반 카드 | 모서리 21pt, 내부 여백 16pt, 밝은 표면색 |
| 날짜 타일 | 약 58×60pt, 16pt 모서리 |
| 헤더/본문 | Android의 headline·title·body 계층에 대응하는 SwiftUI 상대적 글꼴, Dynamic Type 확대 허용 |
| 하단 메뉴 | 다섯 탭의 아이콘·라벨, 선택 표시와 배경색을 Android 메뉴에 가깝게 구성; 안전 영역 밖으로 터치 영역이 밀리지 않음 |

고정 치수를 화면 전체에 무조건 적용하지 않는다. 작은 iPhone과 글자 확대에서는 카드 높이가 콘텐츠에 따라 늘어나며, 지도·일정 분할 영역에는 최소 터치 영역을 확보한다.

## 화면별 적용

1. **공통 뼈대:** `NativeRootView`의 다섯 탭, 선택 상태, 배경·탭바를 Android 기준으로 맞춘다. 시스템 TabView를 유지하고 기본 탭바만 감춘 뒤, `safeAreaInset`에 SwiftUI 사용자 정의 다섯 탭 메뉴를 배치한다. 선택 탭의 배경 표시와 아이콘·라벨 비율을 Android에 맞추고, 하위 `NavigationStack`을 유지해 탭을 바꿨다가 돌아올 때 선택한 여행과 네비게이션 상태가 뜻밖에 초기화되지 않게 한다. 탭 접근성 레이블과 터치 영역을 보존한다.
2. **내 여행:** 이미 구현된 대표 여행/다른 여행/지난 여행 구조를 유지한다. 보라색 카드와 버튼을 Android의 녹색·청색, 헤더 크기와 간격으로 맞춘다. 여행 생성·선택·수정·삭제와 접근성 ID는 그대로 유지한다.
3. **지도·저장:** 지도 검색창·여행 선택기·지도 조작 버튼과 저장 장소의 빈 상태·목록·편집 폼을 공통 간격·카드 규칙으로 정리한다. 실제 지도 캔버스, 마커 좌표, 검색/권한 흐름은 건드리지 않는다. 지도 키가 없어도 지도 외 UI와 다른 탭은 표시된다.
4. **지출·정산:** 지출 목록·추가/수정 폼·참여자·현금 지갑의 섹션 간격과 입력 행을 정리한다. 통화·원화 환산·1/n 계산 및 저장 로직은 변경하지 않는다.
5. **더보기와 하위 화면:** 데이터·기기 정보·안내 목록, 여행 기록·사진, 준비 체크리스트, 항공·숙소 정보, 백업·일정/지도 분할 화면에도 같은 화면 여백·제목·표면·버튼 규칙을 적용한다. 사진 선택과 파일 가져오기/내보내기 등 시스템 화면은 iOS 원형을 유지한다.

## 구조와 상태

공유 SwiftUI 테마는 색상 역할과 간격·모서리·최소 높이만 제공한다. 화면은 이 값을 참조하고, 데이터 로딩/저장/동기화 코드는 기존 `NativeTripStore` 및 화면별 상태 객체가 계속 담당한다. 뷰의 외형 변경이 저장 데이터 마이그레이션이나 네비게이션 경로 변경을 요구해서는 안 된다. Android의 디자인 규칙을 수동으로 복사한 후 값이 어긋나지 않도록 대응표를 코드 옆에 짧게 문서화한다.

## 오류·접근성·검증

- 로딩·빈 결과·오류·권한 거부 상태에서 콘텐츠가 잘리지 않고 재시도/직접 입력 같은 기존 행동이 가능해야 한다.
- VoiceOver 레이블, 44pt 이상의 누르기 영역, 대비, Dynamic Type, 키보드 표시와 홈 인디케이터 안전 영역을 유지한다.
- 기존 iOS 네이티브 UI 테스트와 시뮬레이터 빌드를 실행한다. 첫 화면, 다섯 탭, 여행 상세·일정 분할, 저장 장소, 지출·정산, 더보기의 대표 상태를 작은/큰 iPhone 시뮬레이터에서 확인한다.
- Android 기준 화면과 iPhone 화면을 비교할 때 상태 표시줄과 홈 영역을 제외하고 콘텐츠의 시작선, 카드 폭/높이, 주요 버튼, 정보 위계와 탭바를 점검한다. 플랫폼 차이 때문에 픽셀 단위 완전 동일은 합격 기준이 아니다.
- 기존 작업 트리에 있는 사용자 변경은 보존한다. 변경 범위를 SwiftUI 네이티브 타깃에 한정하고, Git 푸시/배포는 별도 요청이 있을 때만 진행한다.

## 완료 기준

iPhone의 주요 탭과 하위 화면이 Android와 같은 색상·여백·카드·텍스트 위계를 보이며, 화면 전환 및 편집/저장 흐름이 유지되고, 작은 iPhone/큰 글씨에서도 화면 가림이 없다. iOS 빌드와 관련 UI 테스트가 통과하고 대표 화면의 시뮬레이터 비교 결과를 남긴다.
