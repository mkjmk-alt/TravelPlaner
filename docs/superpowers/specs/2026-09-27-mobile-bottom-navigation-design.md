# 모바일 하단 메뉴 재구성 설계

## 목표

웹 앱의 모바일 및 세로 태블릿 하단 메뉴에서 별도의 `지도` 탭을 제거하고, 지도는 `내 여행` 화면의 지도·일정 분할 영역에서 계속 사용한다. 하단에 `예산·지출`과 `여행 기록`을 직접 여는 탭을 제공하며, 예산과 지출은 현재처럼 하나의 화면과 하나의 탭으로 유지한다.

## 범위

- 변경 대상은 웹 앱의 모바일 및 세로 태블릿 하단 메뉴와 그 화면 전환이다.
- 하단 탭은 `내 여행`, `저장`, `예산·지출`, `여행 기록`, `더보기` 순서의 5개다.
- 지도 전용 하단 탭은 없앤다. `내 여행` 기본 화면은 현재 지도와 여행 목록을 함께 보여주는 분할 화면을 유지한다.
- `예산·지출`은 기존 예산 화면, 지출 입력·목록, 현금 정산과 함께 정산 기능을 하나의 화면에 유지한다.
- `여행 기록`은 기존 선택 여행의 기록 패널을 직접 여는 최상위 하단 탭이다.
- 화면 폭이 넓은 데스크톱은 기존 사이드바 및 상단 여행별 바로가기 동작을 유지한다.
- 여행 데이터 구조, 저장소, 지도 검색/마커 동작, 네이티브 앱, 서버 및 인증은 변경하지 않는다.

## 접근 방식

1. **선택 — 최상위 모바일 탭으로 승격:** 기존 모바일 탭 설정과 라우팅 상태에 `예산·지출` 및 `여행 기록`을 추가하고 `지도`를 제거한다. 탭마다 화면을 직접 선택하므로 활성 표시, 브라우저 뒤로 가기, 재실행 복원이 일관된다.
2. **비선택 — 하단 메뉴에 시각적 단축 버튼만 추가:** 내부 화면은 계속 `내 여행` 탭의 하위 화면으로 두고 버튼만 추가한다. 버튼 선택과 저장된 최상위 탭이 어긋나며 화면 이력 복원도 복잡해진다.
3. **비선택 — 예산과 지출을 별도 탭으로 분리:** 사용자가 예산·지출 통합을 선택했으므로 탐색 구조를 불필요하게 늘리고 현재 화면을 쪼개지 않는다.

따라서 최상위 모바일 탭을 5개로 교체하고, 기존 화면을 새 탭에 연결하는 첫 번째 방식을 사용한다.

## 내비게이션 상태와 전환

최상위 루트는 다음과 같이 관리한다.

```js
rootTab: 'trips' | 'favorites' | 'budget' | 'memory' | 'more'
viewMode: 'trips' | 'itinerary' | 'budget' | 'memory' | 'favorites' | 'more'
activeTripId: string | null
tabSnapshots: {
  trips: { viewMode: 'trips' | 'itinerary', activeTripId: string | null },
  favorites: { viewMode: 'favorites', activeTripId: string | null },
  budget: { viewMode: 'budget', activeTripId: string | null },
  memory: { viewMode: 'memory', activeTripId: string | null },
  more: { viewMode: 'more', activeTripId: string | null }
}
```

- 탭 간 이동은 현재 선택한 여행(`activeTripId`)을 유지한다. 유효하지 않거나 삭제된 여행 ID는 기존 정리 규칙에 따라 비운다.
- 현재 `activeTripId`가 하단 탭 이동의 기준이다. 탭 스냅샷은 화면 이력과 복원을 위해 현재 여행 ID를 함께 기록하고, 여행 선택이 바뀌면 새 화면과 스냅샷을 그 선택에 맞춘다.
- 같은 하단 탭을 다시 누르면 해당 루트의 기본 화면으로 돌아간다. `내 여행` 탭은 여행 목록, `예산·지출`은 예산 화면, `여행 기록`은 기록 패널을 기본으로 한다.
- 기존 localStorage 또는 browser history를 새 루트로 정규화한다. 구형 `rootTab: 'map'`은 저장된 여행 ID를 보존해 `trips` 루트의 기본 분할 화면으로 옮긴다. 구형 `rootTab: 'trips'`와 `viewMode: 'budget'|'memory'`는 각각 `budget`/`memory` 루트로 승격한다. 구형 `trips` 스냅샷의 예산·기록 화면과 여행 ID는 새 루트의 스냅샷에 옮긴다.
- 모바일/세로 태블릿에서 `trips` 루트의 지도·일정 분할 동작은 유지한다. `favorites`, `budget`, `memory`, `more` 루트는 지도 없이 콘텐츠를 보여준다.
- 기록 패널에서 장소를 열면 `내 여행`으로 전환해 선택 장소를 지도와 일정 영역에서 확인한다. 별도 지도 루트는 생성하지 않는다.
- 상세 일정 화면의 기존 컨텍스트 복귀 동작은 유지한다. 새 최상위 예산·지출/여행 기록 탭을 내 여행의 하위 메뉴처럼 보이게 하는 뒤로가기 표시는 사용하지 않는다.

## 선택 여행이 없을 때

예산·지출 또는 여행 기록을 선택했지만 현재 여행이 없으면 빈 화면으로 두지 않는다. 선택한 메뉴 제목, 여행이 필요한 이유, `내 여행으로 이동` 동작을 제공한다. 버튼은 `trips` 루트로 이동하고, 기존 여행 선택/생성 흐름을 사용한다. 여행 선택 후 다시 해당 탭으로 이동하면 선택 여행의 내용을 연다.

## 화면과 반응형 동작

- 기존 모바일/세로 태블릿 표시 조건은 유지한다. 데스크톱에서는 하단 탭을 표시하지 않는다.
- 하단 바는 5개의 동일 너비 항목으로 배치한다. 각 항목은 아이콘과 짧은 한국어 레이블을 사용하고, 시스템 하단 안전 영역·최소 터치 영역을 보장한다.
- 좁은 휴대전화에서도 `예산·지출`을 포함한 레이블이 잘리지 않도록 메뉴 내부 여백·간격·글자 크기를 반응형으로 조정한다. 가로 스크롤 메뉴로 바꾸지는 않는다.
- 지도 검색창 노출 규칙은 기존 조건과 연동한다. 모바일에서는 내 여행 지도/일정 화면에만 유지하고, 새 예산·지출 및 여행 기록 탭에서는 숨긴다. 데스크톱 검색창은 지도와 함께 유지한다.
- 모바일 더보기에서 새 하단 탭과 중복되는 예산·지출 및 여행 기록 바로가기는 제거하고 계정, 일정, 백업/복원, 지원 등 나머지 기능은 유지한다. 데스크톱의 기존 사이드바·상단 여행별 아이콘·바로가기는 변경하지 않는다.

## 오류·호환성

- 이전 버전의 저장된 네비게이션 상태를 읽을 수 있어야 한다. 구형 `map` 탭은 `trips`로 이동하며, 여행/즐겨찾기 데이터와 나머지 탭 상태를 삭제하지 않는다.
- 여행이 삭제되거나 현재 기기에서 사용할 수 없는 경우 관련 화면은 여행 미선택 빈 상태로 전환된다.
- 지도 API 키가 없거나 지도 로딩에 실패해도 예산·지출, 기록, 저장, 더보기 콘텐츠 및 하단 탭은 동작한다.
- 모바일 메뉴를 숨기는 데스크톱 표시 조건, 선택 탭의 접근성 상태/레이블, 키보드 포커스와 브라우저 `popstate` 복원을 유지한다.

## 검증 기준

1. 하단 메뉴 테스트는 5개 항목의 순서·레이블·키를 검증하고 `map` 루트가 더는 메뉴에 없음을 보장한다.
2. 내 여행, 저장, 예산·지출, 여행 기록, 더보기 탭 선택이 해당 `rootTab`과 `viewMode`를 설정하고 활성 탭을 맞춘다.
3. 구형 `map`, `trips+budget`, `trips+memory` 상태의 localStorage 및 browser history 정규화가 올바른 루트로 이동하며 유효한 여행 ID와 화면 상태를 보존한다.
4. 예산·지출과 기록 탭 간 이동, 브라우저 뒤로/앞으로, 재실행 후 여행 문맥 복원을 테스트한다.
5. 여행 미선택 빈 상태에서 `내 여행으로 이동`을 제공하고 지도 키가 없어도 다른 탭이 동작하는지 확인한다.
6. 모바일/세로 태블릿에서 5개 탭의 레이블·터치 영역·홈 안전 영역을 확인하고, 데스크톱에서는 기존 사이드바가 유지되는지 확인한다.
7. 내 여행 지도/일정 분할과 해당 화면의 검색창 노출이 유지되고 지도 전용 탭/루트는 표시되지 않는지 확인한다.

## 완료 조건

5개 하단 탭이 저장된 상태·뒤로 가기·여행 문맥과 일치하고, 별도 지도 탭 없이 내 여행 화면에서 지도를 계속 사용할 수 있다. 예산·지출은 통합 상태로 유지되고 여행 기록은 직접 접근 가능하다. 좁은 모바일 폭에서 탭이 읽히고, 데스크톱 내비게이션은 회귀 없이 보존된다.
