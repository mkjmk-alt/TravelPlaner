# TripPlot 앱형 내비게이션 설계

## 목표

현재 단일 WebView 안에 있는 지도·여행·저장·경비·기록 기능을 모바일 앱처럼 사용할 수 있도록 시작 화면, 하단 최상위 메뉴, 여행 상세 화면, 뒤로 가기와 상태 복원을 일관된 규칙으로 연결한다.

## 범위

- 하단 최상위 메뉴는 `내 여행`, `지도`, `저장`, `더보기` 4개를 고정한다.
- `내 여행`은 여행 목록을 기본 화면으로 하며 여행을 선택하면 해당 여행의 일정·경비·기록 화면으로 진입한다.
- `지도`는 지도 전체 화면으로 동작하며 장소 검색·장소 상세·즐겨찾기·일정 추가를 제공한다.
- `저장`은 저장한 장소 목록 전체 화면으로 동작하며 장소를 지도에서 확인하거나 현재 여행의 일차에 추가할 수 있다.
- `더보기`는 계정·설정·백업·지원·약관을 제공한다. 선택 여행의 일정·경비·기록은 여행 상세 문맥에 둔다.
- 일정 화면에서만 지도와 일정의 기존 자유 조절 분할을 사용한다. 나머지 최상위 화면은 한 콘텐츠 영역을 사용한다.
- 마지막 선택 탭·화면·여행·스크롤 위치를 로컬에 복원한다.
- WebView의 브라우저 방문 기록과 별개로 앱 화면 이동 기록을 `pushState`/`popstate`로 관리한다.
- 데스크톱은 기존 사이드바 구조를 유지한다. 모바일과 세로 태블릿은 하단 메뉴를 사용한다.

## 시작·복귀 규칙

1. 최초 실행은 기존 온보딩을 거친 뒤 `내 여행` 목록을 시작점으로 한다.
2. 일반 재실행은 저장된 최상위 탭과 화면을 복원하되 삭제되었거나 접근할 수 없는 여행이면 `내 여행` 목록으로 안전하게 돌아간다.
3. 앱 백그라운드 복귀는 웹 페이지를 다시 로드하지 않고 현재 상태를 유지한다.
4. 공유 링크는 공유 일정 상세를 열고, `내 여행`으로 돌아오는 명시적 경로를 제공한다.
5. 하단 메뉴를 다른 탭으로 바꾸면 그 탭의 마지막 화면을 복원한다. 현재 선택된 탭을 다시 누르면 그 탭의 첫 화면으로 이동한다.

## 화면 상태 계약

```js
{
  rootTab: 'trips' | 'map' | 'favorites' | 'more',
  viewMode: 'trips' | 'itinerary' | 'budget' | 'memory' | 'favorites' | 'more',
  activeTripId: string | null,
  tabSnapshots: {
    trips: { viewMode, activeTripId },
    map: { viewMode: 'trips', activeTripId },
    favorites: { viewMode: 'favorites', activeTripId },
    more: { viewMode: 'more', activeTripId }
  }
}
```

여행 데이터가 삭제되면 해당 `activeTripId`를 비우고 `trips` 목록으로 전환한다. 읽기 전용 공유 여행은 로컬 복원 대상에서 제외한다.

## 뒤로 가기

- 입력 키보드·열린 모달·장소 상세는 먼저 닫는다.
- 여행 상세 화면에서는 직전 앱 화면 또는 `내 여행` 목록으로 이동한다.
- 최상위 시작 화면에서는 Android 시스템 뒤로 가기와 iOS WebView의 기본 종료/이전 동작으로 넘긴다.
- 앱 화면 이동은 WebView `history.state`에 저장해 Android의 기존 `canGoBack()` 흐름과 함께 동작하게 한다.

## 레이아웃

- 모바일·세로 태블릿에서 지도 탭은 지도 pane만 표시한다.
- 내 여행·저장·더보기·경비·기록은 콘텐츠 pane만 표시한다.
- 일정은 지도 pane과 콘텐츠 pane을 자유롭게 조절할 수 있다.
- 하단 메뉴는 고정하며 콘텐츠의 하단 패딩에 안전 영역과 메뉴 높이를 한 번만 반영한다.
- 모바일에서는 최상위 메뉴와 중복되는 상단 아이콘을 숨기고, 상세 화면에 여행명·현재 화면·뒤로 가기를 표시한다.

## 호환성

- 기존 localStorage 여행·즐겨찾기·Supabase 동기화 데이터의 형태는 바꾸지 않는다.
- 기존 Swift `WKWebView`와 Kotlin `WebView` 셸은 유지하고 웹 내비게이션 상태만 공유한다.
- 지도 API 키가 없거나 지도 로딩에 실패해도 하단 메뉴와 콘텐츠 화면은 표시한다.
- 외부 URL 이동, 인증 콜백, 계정 삭제 흐름의 기존 주소 처리는 보존한다.

## 검증 기준

- 순수 내비게이션 helper가 시작 상태, 탭 복원, 동일 탭 초기화, 삭제 여행 정리, 뒤로 상태를 테스트한다.
- 기존 전체 테스트와 lint/build가 통과한다.
- 모바일/세로 태블릿에서 각 메뉴가 지도 또는 콘텐츠를 올바르게 단독 표시한다.
- 일정 상세→저장/더보기→일정 상세 복귀 시 여행과 화면이 유지된다.
- 새로고침 후 유효한 마지막 상태가 복원되고 유효하지 않은 여행은 목록으로 안전하게 이동한다.
