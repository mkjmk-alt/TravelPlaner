# Travel Mapmory 콘텐츠 통합 설계

## 목표

현재 트립 플롯의 지도·장소·일정·경비 기능을 유지하면서 Travel Mapmory에서 확인한 여행 정보와 사진 기반 여행 기록 흐름을 추가한다. 방문 국가 색칠, 음성 메모, 예약 링크는 이번 범위에서 제외한다.

## 범위

### 유지

- 현재 지도와 API 오류 시 사이드바가 계속 보이는 구조
- 저장 장소·즐겨찾기와 국가/지역별 그룹화
- 날짜별 일정, 예비 목록, 경로 표시, 체크리스트
- 여행별 경비·통화·예산·통계·현금 정산
- 로그인, 로컬 저장, Supabase 동기화, 공유 일정
- 현재 데스크톱 classic / 모바일·세로 태블릿 split responsive 정책
- 개인정보처리방침, 이용약관, 계정 삭제 흐름

### 추가

- 여행 기록 화면: 여행 요약, 일정 진행 요약, 사진과 글을 저장하는 저널
- 여행 정보: 항공편과 숙소의 핵심 정보를 여행 단위로 저장
- 여행 목록에서 여행 기록으로 바로 이동하는 진입점
- 사진 기록의 기기 내 저장과 로그인 시 기존 여행 동기화 payload 포함

### 보류

- 방문 국가를 지도에 색칠하는 세계 지도 메모리 레이어
- 음성 메모
- 호텔·투어·항공 예약 링크 및 제휴 전환

## 데이터 계약

기존 trip 객체에 다음 선택적 필드를 추가한다. 기존 저장 데이터에는 기본값을 적용해 마이그레이션 없이 읽을 수 있어야 한다.

```js
{
  travelDetails: {
    departure: '',
    arrival: '',
    flightNumber: '',
    stayName: '',
    stayAddress: ''
  },
  journalEntries: [
    {
      id: string,
      date: 'YYYY-MM-DD',
      title: string,
      body: string,
      imageDataUrl: string,
      createdAt: number,
      updatedAt: number
    }
  ]
}
```

사진은 별도 서버 파일 저장소를 도입하지 않고 기존 로컬/Supabase 여행 payload에 포함한다. 파일은 2.5MB 이하만 허용해 모바일 저장 공간과 동기화 payload가 무한히 커지지 않게 한다. 음성 파일과 외부 예약 URL은 저장하지 않는다.

## UI 설계

- 기존 사이드바 상단 탐색에 `여행 기록` 탭을 추가한다.
- 여행 기록 화면은 기존 sidebar scroll region 안에서 동작하므로 split view에서 브랜드 헤더와 함께 스크롤된다.
- 상단에는 여행명·국가·기간·여행 상태를 보여준다.
- `항공·숙소 정보` 카드에는 편집 가능한 텍스트 입력을 제공한다.
- `여행 기록 남기기` 카드에는 날짜·제목·본문·사진 1장을 입력하고 저장한다.
- 저장된 기록은 최신 수정순으로 보여주며, 사진 미리보기·수정·삭제를 제공한다.
- 읽기 전용 공유 일정에서는 입력·수정·삭제를 막고 데이터만 보여준다.
- 보류 기능을 암시하는 버튼이나 빈 메뉴는 추가하지 않는다.

## 오류 및 호환성

- 기존 trip에 새 필드가 없어도 빈 상태로 렌더링한다.
- 이미지가 제한 용량을 넘으면 저장하지 않고 사용자에게 안내한다.
- 로컬 저장 실패는 기존 `syncStatus` 흐름을 그대로 사용한다.
- 기존 공유/동기화 비교 함수는 새 필드를 여행 데이터로 취급하되, 로컬 bookkeeping만 제외한다.
- 네이티브 앱은 동일 웹 URL을 WebView로 열기 때문에 별도 Swift/Kotlin UI를 만들지 않고 웹 데이터 계약을 공유한다.

## 검증 기준

- 새 순수 helper 테스트가 실패하는 상태를 먼저 확인한 뒤 구현한다.
- 기존 전체 테스트, lint, production build를 실행한다.
- 여행 기록 탭 진입, 항공·숙소 저장, 사진/본문 저장, 새로고침 후 유지, 읽기 전용 차단을 확인한다.
- 지도 API 키가 없는 상태에서도 새 사이드바 화면이 표시되어야 한다.
