# 웹 지도 영역의 독립 지연 로딩 설계

## 목적과 범위

Vite 빌드에서 `App` JavaScript 청크가 최소화 후 621.70 kB로 출력되어 기본 500 kB 경고 기준을 넘는다. 이 경고는 사용하지 않는 쓰레기 파일이 있다는 뜻이 아니다. 현재 앱 코드와 지도 렌더링 코드가 한 청크에 함께 묶였다는 신호이며, 초기 파싱·실행 비용과 변경 배포 시 내려받는 파일 크기를 점검할 필요가 있다.

첫 구조 경계로 지도 영역을 `MapPane` 모듈로 분리하고, 화면에서 지도가 필요할 때만 동적으로 로드한다. 목표는 지도 구현이 앱 전체의 기본 `App` 청크에 들어가지 않도록 하여 각 청크를 경고 기준 아래로 낮추고, 지도 로딩 문제가 여행 목록·일정·저장 등 나머지 화면을 중단시키지 않게 하는 것이다.

대상은 웹앱의 `src/App.jsx`, 새 지도 영역 컴포넌트, 관련 테스트 및 빌드 산출물 검증이다. SwiftUI·Android 네이티브 앱, 제품 기능/데이터 형식, 지도 공급자 변경, 앱 전체의 대규모 상태관리 개편은 범위에 포함하지 않는다.

## 현재 구조와 관찰

- `src/main.jsx`는 런타임 설정을 불러온 뒤 `App.jsx`를 동적 import하지만, 그 App 모듈 자체가 지도 구현까지 정적으로 포함한다.
- `src/App.jsx`는 8천 줄이 넘는 컴포넌트이며, `@react-google-maps/api`의 `GoogleMap`, `OverlayViewF`, `InfoWindow`, `Polyline`과 지도 UI를 같은 모듈에서 가져온다.
- 지도 표시 여부는 기존 반응형 내비게이션 정책에 따라 달라진다. 모바일에서는 `getMobileRootPresentation` 등이 루트 탭에 따라 지도 표시를 결정하고, 데스크톱에서는 현재 동작대로 지도를 계속 표시해야 한다.
- 지도 인스턴스는 현재 지도 화면 외부에서도 장소 상세 조회, 저장 장소에서 지도 위치로 이동, 일정의 지도 범위 조정 등에 쓰인다. 지도 패널이 잠시 언마운트되거나 늦게 마운트되어도 이 흐름이 유지되어야 한다.
- 지도 키가 없거나 Google Maps API 로딩에 실패해도 여행 목록과 사이드바는 계속 사용할 수 있어야 한다. 기존 `getMapAvailability`와 해당 오류·키 상태 UI는 유지한다.
- `vite.config.js`의 `shellManifestPlugin`은 빌드 결과의 모든 번들 파일을 `shell-assets.json`에 기록한다. `public/sw.js`는 이 목록을 프리캐시하므로 새 지도 청크도 오프라인 셸 자산으로 계속 포함된다.

## 선택한 설계

`App`은 앱·여행 상태의 소유자로 남기고, 지도 렌더링과 Google Maps 전용 의존성은 별도 `MapPane` 모듈로 옮긴다. `App`에서 이 모듈을 `React.lazy`/동적 import하고 지도 표시 정책이 참일 때만 마운트한다. 모듈 로딩 중에는 지도 영역 크기를 유지하는 로컬 플레이스홀더를 표시해 레이아웃이 갑자기 이동하지 않게 한다.

### 책임과 인터페이스

| 영역 | 책임 |
| --- | --- |
| `App` | 여행·일정·저장 장소 데이터와 선택 상태, 검색/장소 액션, 반응형 지도 표시 정책, 지도 인스턴스가 필요한 앱 흐름의 조정 |
| `MapPane` | Google Maps 스크립트 로더, 지도 캔버스·마커·경로선·선택 장소 오버레이 및 지도 전용 시각 상태 |
| 지도 로딩 경계 | 코드 청크 또는 지도 API 로딩 중/실패 상태를 지도 영역 안에서만 표시하고, 나머지 앱 UI는 계속 사용 가능하게 유지 |
| 서비스워커 manifest | Vite가 만든 지연 로딩 지도 청크를 다른 앱 셸 자산과 동일하게 precache 대상으로 포함 |

두 모듈 사이의 계약은 명시적인 props와 콜백으로 둔다. 첫 변경에서는 여행/일정의 원본 데이터와 비즈니스 규칙을 `App`에 유지하고, 지도에 필요한 값만 묶어 전달한다. `MapPane`은 지도가 준비되면 `onMapLoad(map)`를, 해제될 때는 `onMapUnmount`를 호출한다. 지도 이동/선택 등 사용자 동작은 콜백으로 `App`에 전달한다. 필요하면 props를 `mapData`, `mapOptions`, `mapActions`처럼 의미 단위로 그룹화하되, 긴밀한 전역 상태 공유나 새로운 상태관리 라이브러리는 도입하지 않는다.

지도 영역의 visibility는 기존 정책을 단일 파생값으로 계산한다. 모바일의 지도 표시 탭/분할 상태에서는 표시하고, 모바일의 지도 비표시 탭에서는 로드하지 않는다. 데스크톱은 현재 지도가 보이는 동작을 보존한다. 검색창의 표시 정책도 기존 `shouldShowSearchBar`를 기준으로 유지한다.

### 지도 인스턴스와 재진입

현재 지도 인스턴스가 쓰이는 장소 검색, 저장 장소에서 지도 포커스, 선택된 일정 범위 맞춤 동작은 계속 작동해야 한다. `App`은 지도 인스턴스 핸들을 보유하고 `MapPane`의 load/unmount 콜백으로 갱신한다. 지도가 보이지 않을 때 요청된 포커스/범위 변경은 버리지 않고 보류 상태로 저장한 다음, 다음 `onMapLoad` 시점에 한 번 적용한다. 지도 언마운트 뒤에는 오래된 인스턴스를 호출하지 않는다. 구현 시 기존 effect/검색 흐름을 확인해 중복 이동이 발생하지 않도록 한다.

## 로딩 및 실패 경험

- 지도 코드 청크가 아직 없을 때는 해당 지도 패널 안에만 중립적인 로딩 표시를 둔다. 사이드바와 선택된 루트 화면은 그대로 유지한다.
- 지도 모듈 import 오류는 지도 전용 경계에서 처리한다. 전역 `StartupRecoveryScreen`으로 앱 전체를 대체하지 않는다. 복구 UI의 재시도 동작은 실패한 모듈을 다시 요청할 수 있게 구현하고, 재시도 중에도 지도 외 기능을 사용할 수 있게 한다.
- Google Maps 키 누락/API 오류는 기존 `getMapAvailability` 분기와 안내를 보존한다. 이는 코드 청크 로딩 실패와 구분된 지도 오류 상태다.
- 지도 비표시 탭에서 지도 모듈과 지도 API를 불필요하게 시작하지 않는다. 지도가 처음 표시될 때 지연 로딩을 시작한다.

## 오프라인·성능 기대치

분할은 모듈 경계를 실제로 늦춰 초기 파싱/실행과 `App` 단일 청크 크기를 줄이는 변경이다. 다만 현재 기본 화면에서 지도가 표시되고 서비스워커가 모든 번들 자산을 precache하므로, 이 변경만으로 첫 방문 전체 전송량이나 설치 시 프리캐시 총량이 줄어든다고 약속하지 않는다. 지도 우선 화면에서는 지도 청크도 곧 요청될 수 있다. 오프라인 콜드스타트 지원을 보존하기 위해 새 청크를 manifest에서 제외하거나 서비스워커 정책을 바꾸지 않는다.

## 범위에서 제외하는 대안

- `chunkSizeWarningLimit`을 높여 경고만 숨기지 않는다.
- 실제 사용 시점이 달라지지 않는 `manualChunks` 이름 재배치만으로 완료 처리하지 않는다.
- 이번 첫 경계에서 지출/정산/기록 등 다른 화면까지 연쇄적으로 쪼개거나 Supabase 패키지를 분해하지 않는다. 지도 경계를 적용한 뒤 산출물 크기를 측정하고, 여전히 500 kB 경고가 남으면 다음 후보를 별도 근거로 판단한다.
- 서비스워커 캐시 전략, 오프라인 기능, 저장 데이터 또는 지도 제공자를 변경하지 않는다.

## 검증 및 완료 기준

1. 기존 지도 표시 정책을 유지하면서 데스크톱과 지도 노출 모바일 화면에서 지도가 표시되고, 모바일의 지도 비노출 화면에서는 지도 모듈이 불필요하게 실행되지 않는다.
2. 지도 분리 후 Vite의 `App` 청크 및 지도 청크 각각이 500 kB 미만이 되고, 빌드 출력에 청크 크기 경고가 없다. 실제 측정에서 하나라도 기준을 넘으면 경고 임계값을 바꾸지 않고 생성된 산출물과 의존성 경계를 추가 조사한다.
3. 지도 모듈 로딩 중/실패, 지도 키 누락, 지도 API 실패 각각에서 사이드바와 비지도 기능을 계속 사용할 수 있다.
4. 장소 검색 및 상세 조회, 저장 장소에서 지도 포커스, 일정 경로선/마커/InfoWindow, 일정 범위 맞춤, 지도 재진입 후 보류 동작 적용이 이전과 동일하다.
5. `shell-assets.json`에 새 지도 청크가 들어가며, 온라인에서 한 번 준비한 뒤 네트워크를 끊는 기존 오프라인 콜드스타트 흐름에서 앱 셸과 지도 청크가 계속 캐시된다.
6. 관련 지도 가용성 테스트에 지연 로딩 표시 정책, 지도 인스턴스 콜백 및 보류 포커스 회귀 테스트를 더한다. 전체 `npm test`, 변경된 파일의 lint, `npm run build`, 생성 청크 크기와 manifest를 확인한다. 데스크톱 및 모바일 브라우저에서 지도/사이드바 전환을 수동 검증한다.

## 작업 트리 보호

현재 작업 트리에는 별도 웹·iOS·Android 변경이 이미 존재한다. 구현은 이 설계가 승인된 뒤 새 작업 계획으로 진행하며, 무관한 파일을 되돌리거나 함께 스테이징하지 않는다. 이 문서는 설계 검토용이며, 제품 소스 코드 변경이나 Git 푸시/배포를 수행하지 않는다.
