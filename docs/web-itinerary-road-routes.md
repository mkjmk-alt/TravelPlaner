# 웹 일정 지도 경로 표시

‘내 일정’ 제목 오른쪽의 경로 버튼에서 **현재 일차 / 전체 일정**, **직선 연결 / 실제 길**, 실제 길의 **자동차 / 도보**를 한 번에 선택한다. 버튼은 가로로 스크롤하는 일정 도구와 분리되어 항상 보이며 현재 연결 방식·이동 방법·표시 범위를 표시한다. 모바일·세로 태블릿은 하단 설정창, 데스크톱은 작은 중앙 팝업으로 연다. 확인·닫기·Escape·바깥 영역 선택으로 닫을 수 있다.

기본값은 기존 직선 연결이다. 연결 방식과 이동 방법 두 설정만 이 브라우저의 로컬 저장소에 보관하며, 표시 범위는 기존처럼 재접속 시 현재 일차로 시작한다. 일차를 아직 선택하지 않았으면 일차 제목을 선택하거나 전체 일정으로 변경하도록 안내한다. 지도 위에는 현재 위치와 지도 이미지 저장 버튼만 남겨 검색창과 경로 설정이 겹치지 않도록 한다.

실제 길은 Google Maps JavaScript Routes 라이브러리의 `Route.computeRoutes()`로 인접한 두 일정 장소 사이의 경로를 요청한다. 일정 방문 순서는 재정렬하지 않는다. 일차별 보기와 전체 경로 보기, 일차 사이 연결에 동일한 설정을 적용한다. 전체 보기에서 빈 일차를 건너뛰더라도 원래 일차 이름과 색상을 유지한다. 예비 목록은 기존처럼 경로를 연결하지 않는다.

## Google Cloud 설정

웹 지도 키가 속한 프로젝트에서 Maps JavaScript API와 **Routes API**를 활성화하고 결제 계정을 연결한다. API 제한이 있는 키라면 Routes API도 허용 목록에 추가한다. 기존 웹사이트 참조 URL 제한은 유지한다. 별도 서버 키를 브라우저에 추가할 필요는 없다.

설정 기준: [Google Routes 시작 안내](https://developers.google.com/maps/documentation/javascript/routes/start), [경로 계산 예제](https://developers.google.com/maps/documentation/javascript/routes/get-a-route).

## 동작과 검증

- 경로는 선택한 이동 수단으로 지도 서비스가 제공하는 도로·보행로를 따라간다. 서비스가 지원하지 않는 지역이나 섬·국가 사이의 이동은 경로가 없을 수 있다.
- 경로가 없는 구간을 실제 도로인 것처럼 직선으로 잇지 않는다. 나머지 계산된 구간은 표시하고, 누락된 구간과 다시 시도·직선 연결 선택을 안내한다.
- 실제 길 모드에서만 요청한다. 한 번에 최대 두 요청을 수행하며 성공한 결과와 진행 중인 요청을 최대 128개까지 세션 메모리에서 공유한다. API 응답과 경로 좌표는 로컬 저장소·여행 데이터·백업 파일에 저장하지 않는다.
- 일차·일정 순서·이동 수단 변경 및 지도 언마운트 시 이전 작업의 결과를 화면에 적용하지 않는다. API 권한·할당량 오류가 나면 대기 중인 요청도 중단한다. 요청 처리는 App의 공유 훅에서 한 번만 수행하고 일정 설정창과 MapPane이 같은 결과를 사용한다.
- 반환된 경로 주의사항과 오류·로딩 상태는 설정창 및 ‘내 일정’ 아래의 안내에 표시한다. 확인으로 닫은 동일 경로의 안내는 설정창을 다시 열어도 되살리지 않으며 경로·이동 방법·재시도·응답 상태가 바뀌면 새 안내를 표시한다.
- 표시 설정은 여행 데이터·일정 순서·도착 시간을 수정하지 않는다. 가까운 순 정렬은 기존처럼 각 일차의 별도 기능이다.

배치 변경 검증: 320·430·820·1440px 브라우저 화면, 하단창·중앙 팝업·짧은 화면의 내부 스크롤, 설정 저장·복원, 닫기와 포커스 복귀, 일차·전체 일정 전환, 안내 닫기와 오류 재시도, 지도 이미지 저장을 확인한다. 이 검증에서는 실제 기본 Google 지도와 통제된 Routes 응답을 사용하므로 운영 Routes API의 권한·결제·지역별 경로 결과 검증을 대신하지 않는다.

실제 키 검증 시: 위치가 있는 장소 세 개 이상인 여행에서 직선과 실제 길의 차이, 자동차·도보 전환, 일차 전환, 전체 경로 보기, 일정 재정렬, 재접속 후 설정 복원을 확인한다. 경로 미지원 지역과 API 접근 오류에서는 지도·일정 조작을 계속 사용할 수 있어야 한다.
