# 네이티브 2단계: 일정 편집·JSON 백업 검증

대상: `TripPlot Native` (`com.travelplaner.app.nativepreview`), 2026-09-21.
요청 ID: `ae855280e0`, `67a0d94470`, `c178b2aac4`. 기존 운영 앱과 웹 데이터는 별도이며 자동으로 읽거나 수정하지 않는다. 승인된 2단계의 일정 편집·파일 이전 기능을 구현하고 아래 환경에서 검증했다. 전체 네이티브 전환이나 출시 검증이 완료된 것은 아니다.

## 사용 방법

1. 내 여행 → 여행 상세 → **일정·예비 목록 편집**을 연다.
2. 예비 목록 또는 일차를 선택하고 **장소 직접 추가**로 이름·표시 이름·주소·현지 시간·메모·아이콘을 입력한다. 아직 지도 검색은 연결하지 않는다.
3. 장소의 작업 메뉴에서 편집, 한 칸 위/아래 이동, 다른 일차/예비 목록 이동, 삭제 확인을 사용할 수 있다. 시간을 바꿔도 순서는 자동 변경하지 않는다. **시간순 정렬**을 별도로 누르면 미정 시간은 마지막, 동일 시간은 기존 상대 순서를 유지한다.
4. **더보기 → 여행 백업 가져오기**, 또는 여행 상세의 **여행 JSON 백업**에서 시스템 파일 선택기를 연다. 파일을 선택하면 미리보기만 나타나며, 확인하기 전에는 DB에 저장하지 않는다.
5. 내보내기는 대상 여행을 선택한 다음 시스템 저장 위치를 선택한다. iOS 파일 앱의 `나의 iPhone → TripPlot Native`에서 Documents의 JSON 파일을 관리할 수 있다. DB와 수신 원본은 이 폴더가 아니라 앱 내부 Application Support에 있다.

## 데이터 보존·제한

- 단일 여행 UTF-8 JSON, 최대 **20 MiB / 100일 / 장소 10,000개 / 중첩 64단계**. UTF-8 BOM은 허용한다.
- 오래된 파일의 누락 ID·번호·기본 필드는 결정적으로 보완하고 미리보기에 알린다. 이미 있는 잘못된 시간·날짜·ID·필드 타입은 조용히 고치지 않고 거부한다.
- 장소 편집은 여섯 입력 필드만 변경하며 좌표·사진·예약·지출·알 수 없는 확장 필드는 보존한다. 숫자 ID `1`과 문자열 ID `"1"`을 구별한다.
- 같은 파일을 반복 가져오면 이전 기록으로 식별하여 중복 생성하거나 이후 수정 내용을 덮어쓰지 않는다. 같은 여행 ID의 다른 내용은 명시적으로 **별도 여행으로 가져오기**를 선택한다. 삭제된 이전 대상은 새 ID로 복원한다.
- 여행과 이전 이력을 한 DB 트랜잭션으로 저장한다. 원본 바이트는 앱 내부 이전 이력에 남긴다. 공유 연결 `sharedId`와 관리 권한 `sharedManagementToken`은 새 여행과 사용자용 백업에서 제외한다.
- Core Data는 원래 스키마를 유지하고, 변경 전 SQLite/WAL을 일관된 복구 사본으로 보관한 뒤 검증한다. Room은 1→2 이전으로 이력 테이블만 추가한다. DB 초기화·destructive migration은 사용하지 않는다.
- 웹 백업은 전역 즐겨찾기·계정 전체를 포함하지 않는다. 기존 웹 가져오기는 새 여행 ID를 만들고 알 수 없는 루트 필드를 제외할 수 있다. 네이티브 파일 간 보존과 웹 가져오기의 지원 범위를 구분한다.

## 검증 결과

- Swift NativeCore: 27개 테스트 통과. 일정 변경, ID 구별, 경계값, 원본 보존, 백업 제한, 실제 Core Data 이전, 중복·충돌·삭제 복원·롤백·재시작을 포함한다.
- Android: JVM 25개 및 기기 테스트 14개(UI 5 + Room 9), nativepreview 빌드/lint, 기존 :app 빌드 통과. 2.0배 글씨에서 가로 화면 입력·스크롤·저장 추가 검사 통과. lint는 오류 0개, 경고 31개다.
- iOS: 최종 UI 테스트 **5개, 실패 0개**. 기본 생성·편집·재실행, 일정 편집·이동, 가로 입력·스크롤·저장, 시스템 선택기 취소, 잘못된 파일·반복 가져오기·실제 파일 내보내기·Android 파일 가져오기를 포함한다. 별도로 최대 접근성 글씨에서 가로 입력·저장 후 세로 복귀 검사도 통과했다. 최종 xcresult: `ios/DerivedData/NativePreviewStage2Final/Logs/Test/Test-TripPlotNativePreview-2026.09.21_12-12-21-+0900.xcresult`.
- 실제 시스템 저장창에서 생성한 `contracts/native/fixtures/ios-export.json`과 `android-export.json`은 JSON 의미상 동일하다. 원본 예제의 좌표·시간·지출·확장 값이 보존되었다.
- 두 파일 모두 격리된 브라우저에서 실제 웹 파일 가져오기를 통과했다. 이름·기간·일정·예비·예산·지출 값을 확인했으며 브라우저 런타임 오류는 없었다. 운영 계정/브라우저 저장소에는 접근하지 않았다.
- 기존 iOS `TravelPlaner` 스킴 빌드, 웹 테스트 81개, 웹 프로덕션 빌드, native:security 검사가 통과했다. 웹 빌드의 500 kB 초과 chunk 경고는 남아 있다.
- Android 실제 파일 선택기에서 iOS 백업을 가져온 뒤, 시험 여행 3개와 이전 이력 2개를 포함한 DB의 여행/이력 데이터를 강제 종료·재실행 전후 비교하여 동일함을 확인했다. 예비 목록의 `09:30`, `persisted memo` 및 가져온 여행의 확장 필드도 확인했다.
- iOS 실제 선택기로 Android 백업을 가져온 후, Core Data의 이전 이력에서 원본 파일의 SHA-256과 원본 바이트가 일치하는지 확인했다. 저장된 여행의 ID 외 모든 필드는 원본 파일과 같았다. 시험 여행 18개·이력 2개의 전체 저장값을 종료·재실행 전후 비교해 동일함을 확인했다.
- AGP 자동 제거 방지 설정 뒤 Room 기기 테스트 4개를 재실행하여 APK와 기존 미리보기 DB가 남는 것을 확인했다.
- [Android 재실행 화면](native-stage2/android-more.png), [iOS 재실행 화면](native-stage2/ios-backup.png). 새 미리보기의 지도·정산 등이 아직 후속 단계임을 앱 안에서도 안내한다.

## 구현 과정의 결정

실행 계획 스킬의 판단 기록을 다음과 같이 남겼다. 아래 순서는 작업 기록 순서다.

1. 기존 미커밋 1단계 소스가 있는 동일 작업 폴더에서 계속 구현했다. 별도 HEAD 작업 폴더로 옮기면 기반 코드가 빠지므로 선택했으며, 추후 커밋 시 관련 없는 변경과 분리해야 한다.
2. iOS 미리보기의 Documents만 파일 앱에 노출했다. DB·수신 원본은 Application Support에 유지한다. 이 공개 범위를 바꾸려면 Documents 노출 설정만 별도로 되돌릴 수 있다.
3. iOS 27의 느린 실패 진단 때문에 최종 UI 검사는 26.5 시뮬레이터에서 했다. iOS 27 고유 동작은 추가 검증이 필요하다.
4. 장소 삭제 확인은 취소 버튼이 명확히 보이는 네이티브 alert를 사용했다. 원래 계획의 confirmationDialog와 표현 방식만 다르고, 삭제 확인과 데이터 계약은 같다.
5. UI와 테스트에서 같은 타입별 ID 처리를 쓰도록 읽기 전용 일차·장소 조회 함수를 추가했다. 배포 전에 외부 공개 API 범위를 정리할 수 있다.

## 직접 검토와 남은 작은 개선

작성자가 일정 순수 로직, 백업 디코더, 저장소의 최신 데이터 재읽기, 이전 이력/트랜잭션, 스키마 이전, 두 플랫폼의 폼/시스템 파일 흐름을 별도로 확인했다. 독립 검토자의 검토 결과는 아니다.

- Android의 JSON 숫자 비교는 원래 표기를 구분하므로 `35.1`과 `35.100000000000001`처럼 의미가 같은 좌표가 다른 플랫폼에서 직렬화되면 충돌 미리보기가 나올 수 있다. 기존 여행을 덮어쓰지 않으며, 이 경우 명시적으로 별도 복사를 선택한다. 숫자 동등성 정규화는 후속 개선으로 남긴다.
- Android lint의 SDK/라이브러리 최신화, 공유 아이콘의 미사용 리소스, 구형 백업 설정 안내 등 경고는 배포 준비 단계에서 정리한다. 이번 단계에서 의존성 전체 업데이트는 하지 않는다.

## 검증 환경과 주의 사항

- iOS 26.5 iPhone 17 Pro 시뮬레이터; Xcode 27. Simulator GUI 앱은 설치 환경에서 열 수 없어 XCTest와 CoreSimulator로 실행한다. GUI 창이 열렸다고 주장하지 않는다.
- Android API 36, `TravelPlaner_API_36` 에뮬레이터. 운영 앱 `com.travelplaner.app`은 제거하거나 데이터를 초기화하지 않았다.
- AGP 기본 connected-test 종료 정리가 시험용 nativepreview/test APK를 제거하는 것을 확인했다. 그동안의 Android 합성 시험 데이터도 함께 제거되어 예제로 다시 생성했다. 이후 `android.injected.androidTest.leaveApksInstalledAfterRun=true`를 설정해 앱과 데이터를 남기도록 했다. 실제 사용자 여행을 입력한 운영 앱에는 영향이 없다.
- 시험 데이터 `NativeQA-*`, `ScheduleQA-*`, `LayoutQA-*`, `UI 여행 *`, `구형 여행`과 예제 JSON을 사용한다. 남아 있는 샘플은 미리보기 샌드박스/에뮬레이터 Downloads에만 있으며 운영 앱 데이터와 무관하다. Downloads 예제와 iOS 합성 여행은 임의 삭제하지 않았다.
- 실물 기기, iOS 16/27 전체 조합, Android API 26 실기기, iCloud/외부 클라우드 파일 공급자, TalkBack/VoiceOver 전체 감사, 강제 전원 차단은 미검증이다. SQLite/Room 실패 롤백과 정상 프로세스 재시작 검사를 물리 전원 차단 검사로 표현하지 않는다.
- 독립 검토자는 사용량 제한으로 실행되지 않았다. 작성자의 직접 검토는 독립 검토 통과를 대신하지 않는다. 배포 전 별도 검토가 필요하다.
- 새 SDK/지도·계정 동기화·전역 즐겨찾기·지출 네이티브 화면은 후속 단계다. 커밋·푸시·운영 배포는 이번 요청에서 하지 않는다.
