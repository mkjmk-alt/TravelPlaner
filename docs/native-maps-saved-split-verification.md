## 현재 상태

별도 미리보기 `com.travelplaner.app.nativepreview`에 구현 중이다. 운영 웹 및 기존 WebView 앱 `com.travelplaner.app`을 대체하거나 배포한 것이 아니다. 네이티브 제한 키가 없어 실제 Google 지도·검색 검증은 미완료이며, **3단계 전체 완료 또는 출시 가능 상태가 아니다**. 사용자의 요청에 따라 이 키 검증은 지출·정산 단계 뒤에 다시 리마인드하는 보류 관문으로 유지한다.

현재 로컬에서 사용할 수 있는 흐름:

- 저장 탭: 여행 없이 직접 장소 등록, 이름·메모 검색, 상세, 지도 보기, 원하는 여행·일차/예비 목록에 복사, 삭제 확인. 삭제해도 복사된 일정은 남는다.

- 휴대폰/태블릿 세로: 상하 분할. 가용 폭 840 및 높이 600pt/dp 이상인 가로 영역: 좌우 분할. 기기 이름이나 전체 물리 화면 크기를 기준으로 하지 않는다.
- 기존 일정의 추가·편집·순서 이동·시간순 정렬·삭제 확인·여행 JSON 백업은 유지한다. 지도 키가 없어도 이용할 수 있다.
- Google 어댑터: 지도 마커는 SDK 지리 좌표로 유지하고 ID별로 차이만 반영한다. 카메라는 명시적인 이동 요청을 한 번만 처리한다. 목록 수정·분할 드래그가 자동 fit 명령을 만들지 않는다. 경로선은 방문 순서 연결선이며 도로 길찾기나 도착 예상 시간이 아니다.

## 데이터 보존

- Swift 원래 모델과 단계2 모델을 그대로 두고 `SavedPlaceRecord`를 추가했다. SQLite 이전 전 회복용 사본을 남기며 여행과 ImportReceipt의 모든 저장 필드/원본 파일 바이트를 비교한다.
- Room 스키마3은 `saved_places`와 sourceKey 고유 인덱스를 추가한다. 1→2 이전을 유지하고 2→3을 추가했으며 파괴적 재생성을 사용하지 않는다.
- 같은 Google placeID는 같은 저장 장소로 처리하고 기존 사용자 메모를 덮지 않는다. 동명 장소, 문자열/숫자 ID는 이름이나 인덱스로 병합하지 않는다.
- 좌표 없는 장소를 0,0으로 대체하지 않는다. 실제 0,0은 유효한 좌표이며 기존 원본 좌표·사진·지출·알 수 없는 필드는 보존한다.
- 새 Google 검색 장소는 placeID와 직접 입력한 이름·메모·시간·아이콘만 영구 저장한다. 제공자 이름/주소/좌표/attribution은 화면 메모리에만 있고 화면 종료 또는 5분 경과 시 폐기한다. 검색어와 SDK 객체를 복원 상태나 DB에 넣지 않는다.
- 단일 여행 JSON 백업에는 전역 저장 장소가 포함되지 않는다. 새 Google 참조의 조회 좌표도 제외된다. 현재 웹에서는 이 참조를 자동 조회해 지도 위치를 복원하지 않으며, 해당 차이는 더보기와 백업 화면에 안내한다.
- 테스트는 UUID 이름의 합성 저장소/여행/장소만 생성한다. 테스트가 삭제하는 것은 해당 합성 DB 또는 명시적으로 만든 합성 저장 장소뿐이다. 기존 앱 저장소, 계정, 실제 여행을 지우거나 읽지 않는다. 미리보기 전체 데이터 초기화/앱 제거는 하지 않는다.
