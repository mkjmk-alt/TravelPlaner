# TravelPlaner Google Play 비공개 테스트 계획

새 개인 Play 개발자 계정의 프로덕션 접근 조건을 충족하기 위한 실행 문서입니다. 테스터 이메일과 피드백에는 실제 여행 예약번호, 계정 비밀번호, 인증 코드 같은 민감정보를 기록하지 않습니다.

## 시작 전 준비

- Play Console 앱 설정과 스토어 등록정보를 완료합니다.
- 서명된 AAB를 내부 테스트에서 먼저 설치·업데이트합니다.
- 비공개 테스트 트랙을 만들고 테스터 Google 계정 12명 이상을 등록합니다.
- 모든 테스터에게 같은 참여 링크와 14일 동안 이탈하지 말아야 한다는 점을 안내합니다.
- 중도 이탈에 대비해 14명 이상을 모집하는 것을 권장합니다.

## 테스터 명단

개인정보가 Git에 올라가지 않도록 실제 이메일은 이 표가 아닌 Play Console 또는 별도 비공개 문서에서 관리합니다.

## 14일 검증 시나리오

1. 앱 설치와 첫 실행, 로그인 없이 여행 생성
2. 앱 강제 종료와 재실행 후 로컬 일정 유지
3. 일차별 일정·장소 검색·지도 마커·현재 위치 권한 허용/거절
4. 항공·숙소 예약 메모와 준비 체크리스트
5. 현지 통화·원화·추가 통화 지출, 예산과 현금 정산
6. 통계 화면과 PNG·CSV·iCalendar·JSON 저장
7. 선택적 이메일/Google 로그인과 기기 간 동기화
8. 공유 링크 생성, 다른 사용자 수정, 생성자의 공유 해제
9. 오프라인 안내와 네트워크 복구
10. 계정 삭제 후 재로그인 불가와 클라우드 데이터 제거
11. 이전 버전에서 새 버전으로 업데이트 후 로컬 데이터 유지
12. 작은 휴대전화와 태블릿에서 레이아웃 확인

## 피드백 질문

- 일정 생성부터 저장까지 막힌 단계가 있었나요?
- 지도 버튼과 현재 위치·외부 경로 버튼의 의미가 분명했나요?
- 통화·결제수단·지출 금액 입력이 화면 크기와 관계없이 편했나요?
- 앱 종료·업데이트 후 데이터가 유지됐나요?
- 공유 링크의 열람·수정·해제 범위를 이해하기 쉬웠나요?
- 오류가 있었다면 기기 모델, Android 버전, 재현 순서를 알려주세요.

## 프로덕션 접근 신청용 기록

- 테스트 시작일과 종료일
- 연속 참여를 유지한 최종 테스터 수
- 사용한 앱 버전 코드와 AAB SHA-256
- 발견한 문제와 수정한 커밋
- 테스트 피드백을 반영한 기능·UI 변경
- 앱이 프로덕션 출시 준비가 됐다고 판단한 근거

공식 요구사항은 제출 시점에 [Google Play 개인 계정 테스트 도움말](https://support.google.com/googleplay/android-developer/answer/14151465)에서 다시 확인합니다.
